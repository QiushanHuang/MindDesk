# MindDesk 3.3.0 acceptance

This release extends the published 3.2 preview → edit → apply → undo workflow. It does not ship the retired terminal implementation. Acceptance is organized around user outcomes.

| Principle | Evidence and acceptance boundary |
| --- | --- |
| Know what is sent | Structured request inspection includes target cards, reference-only context, recorded arrows/labels, custom instructions and revision input. Scope and serialization tests use fictional data. |
| Preserve intent | Changing action, scope or instructions clears the old preview and reconciles the saved-workflow label. Workflow edit state is a value-type draft, persisted only by Save. Native button interactions are not claimed below. |
| Do not invent authority | Proposal validation only accepts editable target IDs and intent-specific outputs. Reference-only IDs and unknown or duplicate placements are rejected. |
| Prevent stale changes | Apply compares the frozen target snapshot and current reference/link content before mutation. Changed reference text or link labels are rejected without creating records. |
| Recover from failure | Invalid proposals, process failure, cancellation and timeout leave the canvas unchanged. Summary, grouping and task apply/undo tests restore the expected records and positions. |
| Understand model limits | Actual Codex runs used a fictional prototype comparison and unknown budget. A Chinese preview and feedback-driven English replacement kept the budget unknown. This verifies those cases, not universal model accuracy. |
| Preserve existing work | Current grouped canvas/layout, quick note and resource/task behavior are retained from the published main branch. Source data is not moved by this release. |
| Make the package inspectable | The release scripts require clean source, verify the package/runtime policy, generate build and bundle manifests, and verify DMG/ZIP checksums. See attached artifacts for package-specific digests. |

## Reproducible checks

```sh
swift test --build-system native
swift test --build-system native -c release
MINDDESK_ORGANIZER_LIVE_SMOKE=1 swift test --build-system native --filter CodexOrganizationServiceTests.testSignedIn
MINDDESK_DOCUMENTATION_PREVIEWS="$PWD/.build/documentation-previews" swift test --build-system native --filter DocumentationPreviewTests
./script/verify_s0_private_canvas.sh --repo-root "$PWD" --package-manifest-only
./script/verify_release_metadata.sh
```

The live tests are opt-in, use synthetic content and consume the signed-in Codex account's usage. The documentation renderer uses isolated settings and an in-memory store.

## Observed evidence

- Debug suite on the release implementation: 724 tests, 2 live-model opt-in skips, no failures; component renders were enabled.
- Release suite: 724 tests, 3 opt-in skips, no failures. The opt-in live tests and documentation renderer were exercised separately.
- Release policy, release metadata, artifact-verifier self-tests, packaging-failure diagnostics, workflow guards, worktree guards and UI-smoke script guards passed locally.
- Published-base baseline: 715 tests, 2 opt-in skips, no failures.
- Independent code review found three presentation defects: misleading link direction, a stale workflow label, and incomplete revision inspection. All three were fixed and re-reviewed with no remaining material defect in the reviewed scope.
- The signed-in Codex 0.153.4 service passed two live tests in 30.45 seconds, including context, language instructions and feedback. The service used its supported executable path and constrained desktop PATH; no CLI installation or user configuration was modified.
- Chinese result: “团队已同意下周比较两个原型。目前尚无已获批准的预算，预算金额仍未知。”
- Revised English result: “The team agreed to compare two prototypes next week, but the budget remains unknown.”

## Native UI limitation

The native computer-use bridge returned `Sky Computer Use native pipe closed before response`, including after resetting the connection. The light/dark screenshots are renders of the actual SwiftUI/AppKit components, not proof of clicks or keyboard interaction in the installed application. Saved-workflow Save/Cancel, workflow switching and inspection should still receive a manual interaction pass on the installed app. This limit does not turn a passing test suite into full daily-use acceptance.

重点验证“输入看得清、只改允许的对象、来源变化时停止应用、失败不写入、应用后可撤销”。真实模型测试使用虚构内容，未发送个人工作区材料。原生 GUI 自动化连接不可用，已明确区分代码测试、组件渲染、真实模型请求与安装后的交互验收。安装时保留旧 App 和一致的数据备份，并单独检查安装包与运行版本。
